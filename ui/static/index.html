    How it works

    One event loop, two speeds, one epoch counter

    What each piece does

    Interruption taxonomy
    Every barge-in is classified in under a millisecond as a slot revision ("make it New York"), a retraction ("never mind") or an intent switch ("forget the flight, my TV is broken"). Each one gets its own cancel-and-replan policy, so a slot revision only redoes the work that depended on the changed slot.
    Epoch-guarded grounding
    Each interruption increments an epoch. Perception and tool outputs carry the epoch they were started in, and any stale output is dropped. That covers the race where a call slips through cancellation.
    Uncertainty-aware ASR
    Two independent Whisper decoders run. When they disagree, or the word-level probability on a slot value is low, the agent asks "did you say Austin or Boston?" instead of acting on a guess. The candidates come from what was actually heard.
    Zero-shot tools
    Tools are ranked by overlap with the manifest's name, description and arguments, plus a bonus when every required argument can be filled. Arguments are built by what each schema field means (city, date, name, enum, nested object). Answers come from whatever fields the result returns.
    Visual grounding
    Printed-label OCR (tried at several rotations, including inverted) is combined with CLIP zero-shot on a centre crop. The 512-d CLIP embedding is passed to lookup_manual for hybrid search. If vision finds nothing, the agent asks the user rather than guessing a port type.
    Safety by construction
    At most 3 fillers, never the same one twice. State-modifying calls are deduplicated by argument hash. Replies promise actions ("booking it now") and only claim them once the tool has finished. Every spoken action carries a snapshot.
