    how it works

    A fast path that answers, a slow path that works.

    Built for Samsung PRISM Theme 05. Every event is handled twice: once, immediately, to acknowledge and update what the agent believes; and once in the background, where tools, speech recognition and vision run without blocking the conversation. Anything started under an older belief is cancelled or thrown away.

    The six rules it lives by

    Answer before thinking
    The fast path runs inline on every event and takes a few milliseconds on the harness clock. It updates the slots, stops stale speech, gives a short acknowledgement and cancels work the caller just made obsolete — without waiting on anything slow.
    Old answers expire
    Each correction bumps an epoch counter. Tool calls and perception jobs remember the epoch they started in; a result that comes back from an older epoch is dropped instead of being read out.
    Ask when unsure
    When two transcriptions disagree on something that matters — Austin or Boston — the agent asks one short question rather than guessing.
    Tools from their schema
    Tools are matched from their names, descriptions and argument schemas, so a tool added at runtime can be called without code changes. Arguments are filled from what the caller said; missing required ones are asked for.
    Look, then say what it saw
    Camera frames go through OCR and CLIP. A confident match is used directly; an ambiguous one is read back to the caller for confirmation.
    Never do it twice
    Fillers are capped at three per turn. Every state-changing call goes through an idempotency ledger, so a retry, a repeat or a reconnect cannot book the same thing twice.
